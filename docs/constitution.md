# Constitución

1. **Stack mínimo**: Astro 7.x con Node 26 por decisión explícita del maintainer; verificar desarrollo, CI y runtime generado sin degradación automática a Node 24. El adaptador actual requiere normalizar explícitamente los metadatos de Build Output API a `nodejs26.x` y comprobarlos antes del despliegue. No incorporar librerías ni frameworks adicionales, salvo para tests y las siguientes excepciones autorizadas antes de su instalación:
   - TailwindCSS v4 (junto con su plugin de Vite `@tailwindcss/vite`) — estilos.
   - `@astrojs/vercel` — adaptador de producción para Vercel con runtime Node, incluidas las rutas dinámicas, middleware y server islands; reemplaza `@astrojs/node` como contrato principal.
   - `pg` — cliente PostgreSQL para la persistencia externa (regla 5).
   - `argon2` — hash de contraseñas con argon2id.
   - `@astrojs/markdown-satteri` — pipeline de Markdown first-party de Astro para renderizar el cuerpo de las notas a HTML en la colección live.
   - `sharp` — motor nativo de imágenes para `astro:assets` en build y validación/optimización de imágenes editoriales en Node.
   - `@aws-sdk/client-s3` y `@aws-sdk/s3-request-presigner` — acceso del servidor a Neon Object Storage y URLs firmadas temporales para carga y lectura; sin credenciales en el cliente.
   - `typescript`, `@types/node` y `@types/pg` — herramientas y declaraciones de desarrollo para comprobar tipos; no se incorporan al runtime desplegado.
2. **Spec antes que código**: leer `docs/constitution.md` y la spec activa antes de tocar código; no añadir dependencias ni cambiar formatos sin actualizar antes la spec.
3. **Separación de capas**: pages (rutas), layouts (estructura), components (UI), content collections (contenido editorial), server islands (autenticación y escritura).
4. **Tests obligatorios**: al terminar cada tarea se ejecutan y se informa el resultado real. Los tests permanecen versionados en `dev` y `main`; CI/build pueden instalar dependencias de tests, pero el despliegue excluye tests, fixtures, cobertura y herramientas exclusivas de tests de los estáticos y funciones. Verificar los artefactos generados, no solo `devDependencies`.
5. **Persistencia externa y despliegue**: Vercel con runtime Node (no Edge), PostgreSQL en Neon con conexión agrupada para la aplicación y conexión directa con privilegios separados para migraciones. Las imágenes editoriales se almacenan en el bucket privado `lawhobucket` de Neon Object Storage (verificado: existe, rechaza lectura anónima y está vacío), no en el filesystem efímero. Docker/VPS/Nginx quedan como referencia opcional heredada, no como contrato de producción ni requisito de volúmenes persistentes. No eliminar sus archivos sin confirmación.
6. **Idioma**: variables en inglés, mensajes de usuario en español, contenido del sitio en español e inglés vía i18n (español por defecto).
7. **Migraciones y cuentas**: scripts independientes con `pg`, historial con checksums, ejecución serializada y transacciones por migración en el mismo cliente; ejecutar antes del build y detener el despliegue ante fallos. Conservar SQL histórico: `001` incluye una nota de ejemplo, `002` es contenido opcional excluido por defecto y `003` es obligatorio. Verificar el esquema antes de adoptar una base existente. Crear escritores mediante CLI de mantenimiento con contraseña ingresada de forma segura y `hashPassword()` Argon2id; sin registro público ni reseteos automáticos en despliegues.
8. **Carga y entrega de imágenes**: conservar el límite inclusivo de 5 MiB, JPEG/PNG por magic bytes y optimización con `sharp`. El navegador carga mediante PUT firmado a un objeto privado pendiente y acotado al usuario; el servidor revalida sesión, propiedad, tamaño y dimensiones, y escribe una clave final única antes de guardar la nota. Añadir `notes.image_key` nullable sin alterar migraciones previas; conservar `image_url` y `data.image` con URL estable `/media/<key>`, nunca con URLs firmadas persistidas. La ruta entrega una redirección con GET firmado nuevo y controla acceso a borradores. Eliminar el objeto anterior solo después del éxito en base de datos; el borrado lógico no elimina imágenes.
9. **Configuración y aislamiento**: usar `astro:env/server` en la aplicación, sin `dotenv` en runtime. Requerir `AWS_ENDPOINT_URL_S3`, `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` y `STORAGE_BUCKET` como secretos del servidor al utilizar almacenamiento. Los scripts independientes pueden usar `process.env` y `process.loadEnvFile()`. Separar secretos y ramas Neon de desarrollo/Preview/producción; las credenciales privilegiadas de migración no pertenecen al runtime ni a previews no confiables.
